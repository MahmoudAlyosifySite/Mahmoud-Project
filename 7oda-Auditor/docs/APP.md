# 7oda Auditor — iOS app

The app names who is holding the phone, and with which hand, from how the hand absorbs a
short random Taptic vibration. It is fully offline: no network code, no analytics. The
algorithms live in the `AuditorCore` package (see `SPEC.md`); the app adds the device layer,
the two recognizers' plumbing, storage and the screens.

## Architecture

```
Auditor/
  AuditorApp.swift          @main, creates AppModel.live() and injects it into the environment
  Device/
    MotionRecorder.swift    one CMMotionManager, accel + gyro + device motion at 100 Hz,
                            12 s ring buffer, snapshot(from:to:), measured rates, ref-counted start/stop
    HapticPlayer.swift      CHHapticEngine (haptics only, no auto-shutdown, restarts on reset/stop),
                            pure pattern(for: ChallengeSpec) per SPEC 3.5, play() returns hapticStart
    CheckRunner.swift       seed (SecRandomCopyBytes) → ChallengeGenerator → play → wait →
                            snapshot → Recording; DeviceSupport (model id, iOS, app version)
  ML/EmbeddingEncoder.swift Core ML wrapper for HandEncoder (generic MLModel API)
  Model/
    AppModel.swift          @Observable @MainActor state and every flow (calibration, checks,
                            test runs, signal check, adaptive learning, recompute, export)
    PatternAnalyzer.swift   process → quality gate → v0 features + v1 embedding
    EnrollmentFlow.swift    pure state machine of the Enroll sheet
    AppSettings.swift       recognizer choice and thresholds (tolerant decoding)
    Records.swift           Person, StoredEmbedding, CheckLogEntry, DecisionSummary
    Exporter.swift          JSON Lines, features CSV, checks CSV, anonymized names
  Storage/EncryptedStore.swift  AES-GCM files, Keychain key provider
  Views/                    SwiftUI screens (Root, Calibrate, Who's holding?, People, Enroll, Lab)
  Models/HandEncoder.mlpackage  compiled by Xcode to HandEncoder.mlmodelc in the bundle
  Assets.xcassets           AppIcon (1024 px, from tools/make_icon.py), AccentColor
AuditorTests/               XCTest, hosted in the app, runs in the Simulator
```

The Xcode project is generated by `tools/gen_xcodeproj.py` (Xcode 16 synchronized folders:
every file under `Auditor/` belongs to the app target, every file under `AuditorTests/` to the
test target; Info.plist is generated from build settings).

## The two recognizers

Every check runs both on the same patterns; the selected one answers, the other is logged.

| | v0 | v1 (default, DECISIONS D12) |
|---|---|---|
| Per pattern | `FeatureExtractor.extract` (calibration-relative) | `EncoderInput.build` → Core ML `HandEncoder` → 128-d unit embedding |
| Model | `Identifier` (Gaussian, SPEC 9) | `EmbeddingIdentifier` (cosine prototypes, SPEC 14.3) |
| Samples | `TemplateSample` (`samples.json`) | `StoredEmbedding` = `EmbeddingSample` + recording id + encoder version (`embeddings.json`) |

Both kinds of samples point to the raw recording they came from, so they can be recomputed.
If the model cannot be loaded, v0 answers and every screen shows a note. The Lab setting
"Answering recognizer" switches the default back to v0.

## Data flow of one check

1. `CheckRunner.record`: sensors warm for at least 0.5 s; 8 random bytes seed the challenge;
   the pattern plays; `hapticStart` is `systemUptime` read right before `start(atTime:)`; after
   `duration + postRoll + 0.1 s` the window `[start − preRoll − 0.1, start + duration + postRoll + 0.1]`
   is cut from the ring buffer into a `Recording` (SPEC 4).
2. `PatternAnalyzer`: `SignalProcessor.process` → `QualityGate.evaluate` (mode `handheld`; `onTable`
   for calibration) → v0 features and the v1 embedding.
3. A failed pattern shows its SPEC 6.3 message and is retried (at most 3 retries per slot).
4. After each clean pattern both recognizers decide on all clean patterns so far; the check stops
   when the answering one is no longer `needMorePatterns` (at most `maxPatterns`).
5. Result card: "Name · right hand" with per-person bars, or Unknown with the reason; patterns
   used and seconds. With the hand challenge (SPEC 9.6) a random hand is requested first.
6. With "Learn from confident checks" on, each recognizer adds the check's patterns as adaptive
   samples when its own decision is confident (SPEC 9.5 / 14.3) and names the same person and
   hand as the answer (and the hand challenge, if any, passed); at most 20 per prototype.
7. Every recording is stored; the check (both decisions) is appended to `checks.json`.

## Screens

- **Calibrate** (first run and Lab): 20 patterns flat on a table; at least 12 must pass. "Skip for
  now" is offered on first run (quality checks then use absolute thresholds).
- **Who's holding?**: big button, status while playing, result card, notes.
- **People**: sample counts per hand and accessory prototypes; add a person; detail with rename,
  add accessory (5 patterns per hand), re-enroll (replaces the samples without accessory), delete.
- **Enroll** (sheet): name → checklist (watch, rings, bracelets off) → right hand: sitting,
  standing, fresh grip × 5 → left hand: same → summary → Save. Progress ring and live quality
  feedback; a failed pattern repeats its slot; after 3 failures in a row the app waits for a tap.
- **Lab**: signal plot (Swift Charts: accel-HP and gyro-HP magnitude, aligned template, event
  markers) with all quality metrics; both recognizers' last decisions with distances and margins;
  test run with ground truth and a confusion matrix per recognizer; settings (recognizer, v0
  absFactor / nameMargin / handMargin, v1 slack / nameMargin, maxPatterns, minNCC, minPeakMargin,
  hand challenge, learning); signal check (3 patterns, SNR per channel, "Taptic response visible");
  device info; export; recalibrate; recompute; delete all data.

## Storage and security

- Folder: Application Support/Auditor. Files: `people.json`, `samples.json`, `embeddings.json`,
  `calibration.json`, `settings.json`, `checks.json`, `recordings/<uuid>.json`.
- Every file is sealed with AES-GCM (CryptoKit, 256-bit key, random nonce, combined format) and
  written atomically with `.completeFileProtection`.
- The key is created on first use and kept in the Keychain as a generic password with
  `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` (not in backups, not migrated). Tests inject a key.
- Raw recordings are kept so features and embeddings can be recomputed when the calibration,
  `FeatureExtractor.version` or the model changes (done automatically at launch and after a
  calibration; also "Recompute features" in Lab).
- Export (Lab) writes `recordings.jsonl` (SPEC 4 JSON Lines), `features.csv` and `checks.csv` to a
  temporary folder and opens the share sheet. Names can be replaced by P01, P02, … Exported files
  are not encrypted; deleting all data removes the folder (the Keychain key stays).

## Run on a device

1. Xcode 16 or newer (CI uses Xcode 26.3 with the iOS 26 SDK). iPhone with iOS 17 or newer.
2. Open `Auditor.xcodeproj`, select the `Auditor` target → Signing & Capabilities → pick your Team
   (change the bundle identifier if it is taken).
3. Choose your iPhone and Run. Allow Motion & Fitness access when asked.
4. Calibrate on a hard table, add people in People, then use Who's holding?.

To regenerate the project: `python3 tools/gen_xcodeproj.py`. To redraw the icon:
`python3 tools/make_icon.py` (needs Pillow).

## Simulator limits

The Simulator has no motion sensors and no Taptic Engine. The app launches, every recording
screen explains why it cannot record (buttons are disabled), and `EmbeddingEncoder` runs on the
CPU. The unit tests run there with synthetic recordings (damped bursts at the challenge events,
gravity and noise) and an in-memory runner, covering: haptic pattern construction, the encrypted
store, the enrollment state machine (including failed patterns), JSON Lines export, the bundled
Core ML model, and calibration → enrollment → checks with both recognizers.
